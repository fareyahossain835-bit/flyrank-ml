Abstract

Search visibility and discoverability can change over time. Identifying items that may experience declining search performance can help teams prioritize investigation and make better use of limited analytical resources. This capstone explores a supervised machine learning approach to identifying potential future performance declines using historical search-performance data.

The workflow aggregates records into monthly observations, creates historical features, and aligns each observation with a subsequent month's target. A continuity check is applied so that lag features do not incorrectly treat non-consecutive months as adjacent. A baseline model, Logistic Regression, and Random Forest are compared using classification and ranking-oriented evaluation metrics. In the currently reported notebook results, Random Forest achieves an accuracy of 0.5522, an F1-score of 0.5747, and a ROC-AUC of 0.5860. These results indicate a modest predictive signal and motivate further validation rather than supporting claims of reliable prediction or causal SEO impact.

The study is intended as a decision-support experiment. It does not attempt to reverse-engineer Google's ranking algorithm, guarantee ranking improvements, or establish that any particular action causes a search-performance change.

Keywords: Machine Learning, Search Performance, Discoverability, Classification, Random Forest, Logistic Regression, Feature Engineering, Decision Support

1. Introduction

Search performance is influenced by many factors, and observed changes in impressions, clicks, click-through rate, and average position can be difficult to interpret at scale. Analysts may need to review many items to determine which ones deserve closer investigation. A structured analytical workflow can help prioritize that review.

Machine learning offers one possible approach: learn patterns from historical observations and estimate whether an item is likely to meet a defined future-decline criterion. Such estimates should be interpreted as signals for further investigation, not as definitive explanations of why search performance changed.

This project develops and evaluates a comparative modelling workflow using the approved FlyRank ML Internship dataset. It focuses on temporal feature engineering, correct target alignment, model comparison, and transparent reporting of limitations.

2. Research Objectives

The capstone addresses the following objectives:

  1. Prepare monthly search-performance observations for supervised learning.
  2. Construct historical features while preserving correct month-to-month relationships.
  3. Compare a baseline model with Logistic Regression and Random Forest.
  4. Evaluate classification performance using multiple metrics instead of relying on accuracy alone.
  5. Assess whether the results justify further experimentation and validation.

3. Data and Responsible Use

The experiment uses the approved starter dataset supplied for the FlyRank ML Internship. Records are aggregated into monthly observations for the modelling workflow. Search-performance measurements provide the basis for historical features and the subsequent-period prediction target.

Temporal data preparation

Monthly observations must be aligned carefully. If an item has records for January and March but no February record, January must not be treated as the immediately preceding month for March. The workflow checks the previous month's date and excludes invalid month transitions from lag-feature calculations.

Privacy and responsible use

The dataset's pseudonymous identifiers are used only where needed for grouping, joining, or validation. They are not intended to serve as predictive features, and no attempt is made to identify the underlying entities.

This publication presents aggregate model metrics rather than raw client-level records. It does not publish private client identifiers, URLs, raw search queries, or unapproved data extracts.

4. Methodology

4.1 Data preparation and aggregation

Search-performance records are transformed into monthly observations. The preparation workflow establishes the time period for each observation and constructs the features used by the predictive models. The modelling dataset covers feature months from January 2025 through May 2026, with corresponding target months from February 2025 through June 2026.

4.2 Feature engineering

Historical search-performance measurements are used to represent prior behaviour. Lag features include previous-period impressions, clicks, position, and click-through rate where valid historical observations are available. Missing prior-period values are retained as missing rather than being fabricated from non-consecutive months.

4.3 Target definition

The supervised target represents whether an observation meets the project's defined future-decline criterion in the following month. The target is shifted forward by one calendar month so that features from a given month are not accidentally paired with a target from an unrelated period. The precise decline rule is the one implemented in the accompanying notebook.

4.4 Models compared

  • Baseline: A reference model used to contextualize the performance of the learned models.
  • Logistic Regression: A conventional classification model that provides a comparatively simple benchmark.
  • Random Forest: An ensemble of decision trees that can capture non-linear relationships between input features and the target.

4.5 Workflow overview

Monthly records → Temporal validation → Feature engineering → Future-target alignment → Model training → Evaluation → Decision-support interpretation

The goal is to identify candidates for further review, not to automate SEO decisions without human assessment.

5. Evaluation Metrics

Several metrics are reported because each captures a different aspect of classification performance:

  • Accuracy: The proportion of predictions that are correct.
  • Precision: The proportion of predicted positive cases that are actually positive.
  • Recall: The proportion of actual positive cases identified by the model.
  • F1-score: The harmonic mean of precision and recall.
  • ROC-AUC: A measure of how well the model separates positive and negative cases across classification thresholds.
  • Average Precision: A summary of the precision-recall curve, useful when assessing positive-class retrieval.

Accuracy alone is insufficient to determine whether a model is useful. Precision, recall, threshold behaviour, ranking performance, and the practical cost of false positives and false negatives also matter.

6.3 Main observations

In the reported results, Random Forest has the highest accuracy, recall, F1-score, ROC-AUC, and Average Precision among the three models. Its ROC-AUC of 0.5860 is above 0.5, but remains modest. This suggests limited separation between the two classes rather than strong predictive performance.

Logistic Regression has a lower F1-score than Random Forest in the reported table. The baseline remains useful as a reference, since a more complex model should only be preferred when its improvement is consistent and meaningful under an appropriate validation design.

These findings should be treated as preliminary. They do not establish that the model will generalize to new clients, future periods, or different search environments.

7. Discussion

The comparison illustrates how historical search-performance features can be used in a supervised classification workflow. The Random Forest model performs best on several reported metrics, but the overall performance is not strong enough to support unsupervised operational decisions.

A practical use case would be to create a shortlist of items for analyst review, then combine model output with domain knowledge and additional evidence. Any such workflow would require a carefully chosen threshold, validation on genuinely unseen periods or entities, and monitoring for changes in data quality and performance.

The project also highlights the importance of correct temporal preparation. Misaligned lag features can create misleading training examples and undermine the validity of evaluation results. Calendar continuity checks are therefore an essential part of the workflow, not merely a technical detail.

8. Limitations and Future Work

  • Modest performance: The current metrics indicate limited predictive strength. Additional improvements and validation are needed.
  • Temporal validation: Future work should evaluate the model using a clearly documented time-based holdout or walk-forward validation strategy.
  • Class imbalance: The target distribution may affect the interpretation of accuracy and other metrics.
  • Feature availability: Missing historical observations can limit which features are available for an item.
  • Generalizability: Results from the available dataset may not generalize to different sites, industries, or future periods.
  • Operational usefulness: A model score is not an explanation of why a decline occurred. Analyst review and additional evidence remain necessary.

Future directions

Further work could include stronger temporal validation, calibration analysis, threshold selection based on business costs, feature importance analysis, and comparison with additional simple baselines. The workflow should also be tested for stability across different periods before being considered for practical deployment.

9. Conclusion

This capstone explores a machine learning workflow for identifying potential future search-performance declines using historical monthly observations. It combines temporal feature engineering, continuity validation, target alignment, and a comparison of a baseline model, Logistic Regression, and Random Forest.

In the currently reported results, Random Forest performs best on several evaluation metrics, although its overall predictive signal remains modest. The experiment demonstrates a structured approach to evaluating the task, while emphasizing that more rigorous validation is needed before the results can support real-world decisions.

The intended contribution is a transparent, reproducible decision-support experiment—not a claim to predict Google's ranking algorithm or guarantee search visibility improvements.
